# Reporting, global search, and CSV export

AsterForge V1 provides an authenticated global identifier search and bounded operational reports.
All results are read-only toward Asterisk. The backend is the authoritative permission boundary;
the UI hides unavailable actions only as a convenience.

## Global search

`GET /api/v1/search?q=<term>` accepts a 2–100 character term and returns at most 20 results per
category. Results are grouped by their `entity_type`, and categories are omitted unless the actor
has the corresponding effective permission:

| Search category | Required permission |
| --- | --- |
| Active server name or hostname | `server.read` |
| PJSIP endpoint or trunk identifier/label | `asterisk.read` |
| Caller/connected number, UniqueID, or LinkedID from CDR data | `call.read` |

Archived servers and all their related identifiers are excluded. `truncated: true` means the
client should refine the term; the API does not offer an unbounded search mode.

## Reports

Use `GET /api/v1/reports/{family}` with timezone-aware `from_time` and `to_time` query parameters.
An optional `server_id` narrows the report. `limit` is 1–1000 (default 100), `offset` is capped at
10,000, and `has_more` reports whether another bounded page exists. Every range must be positive
and no longer than 31 days.

All families require `report.read` plus the data-domain permission shown below:

| Family | Data represented | Additional permission |
| --- | --- | --- |
| `server-availability` | Recorded Asterisk connection-unavailable alert episodes | `asterisk.read` |
| `calls` | CDR call history | `call.read` |
| `failures` | CDR records whose disposition is not `ANSWERED` | `call.read` |
| `trunk-availability` | Persisted trunk state transitions | `asterisk.read` |
| `endpoint-availability` | Persisted endpoint observations | `asterisk.read` |
| `incidents` | Incident opening and resolution history | `incident.read` |
| `host-storage` | CPU, memory, load, and recording-storage samples | `server.read` |

Reports reflect only data persisted by configured and available collectors. In particular, an
empty availability report means no matching persisted unavailability episode or observation was
recorded in the requested range; it is not an uptime guarantee.

## CSV exports

`GET /api/v1/reports/{family}/export` accepts the same family, range, server filter, and a
1–1000 row `limit`. It requires `report.read`, `report.export`, and the family's data-domain
permission. Exports are generated by the backend, include a UTF-8 byte-order mark for spreadsheet
compatibility, and are capped at 2 MB in addition to the row and date limits.

Fields are encoded with standard CSV quoting. Text cells beginning with spreadsheet formula
prefixes (`=`, `+`, `-`, `@`, tab, or carriage return) receive a leading apostrophe to mitigate
formula injection. Treat exports as operational data and store/share them according to local
access policy.

The Reports & exports page exposes search, family/range selection, bounded result tables, and the
CSV action only when the current user has `report.export`.
